# Stable camera exposure for object controls

A hand changes the scene brightness and colour distribution. Automatic webcam exposure/white balance can then change the appearance of the remaining objects, breaking optical flow or changing detector results.

The live app now waits 1.8 seconds after starting cameras, then attempts to lock exposure at its current value. Keep hands out briefly during this settling period. Each camera has **Lock exposure / colour** and **Auto exposure** buttons plus a verified status. If lighting changes substantially, enable Auto exposure, let the image settle, then lock again.

The browser path checks advertised manual-exposure support, preserves the current exposure duration and available colour temperature, applies constraints and checks `getSettings()` before claiming success. When the browser does not expose manual controls, the local Logitech C270 path sends bounded UVC controls through `uvc-util`: preserve exposure duration, gain and colour temperature; set manual exposure and disable auto white balance; read the settings back. An ignored write is a failure, not a success. Only one connected C270 is supported by this native selector; it refuses ambiguous identical cameras and does not touch an iPhone or another camera by accident.

The workspace's actual C270 was read in auto mode (8), at exposure 333 × 100μs = 33.3ms, gain 24, auto white balance enabled. Manual mode (1) and auto-white-balance off were then verified. This preserves the current exposure; it does not promise a short shutter or remove motion blur. Locks may reset after USB reconnection or another app changes the camera, so the app reapplies the lock after stream startup. Capture and physical hand-entry/exit behavior still need an operator check under the current lighting.

The local helper comes from [jtfrey/uvc-util](https://github.com/jtfrey/uvc-util), MIT licensed, commit `8110da7025c95eea3096a7181af9a46c0cc7ac37`. Its source and binary live in ignored `outputs/tools/uvc-util`; nothing is globally installed. To reproduce on macOS with Xcode Command Line Tools, clone the repository there, check out that commit, then build its four `.m` files from `src` using the upstream command in its README (`clang` with the IOKit and Foundation frameworks). Preserve its LICENSE. Unsupported/missing helper cases are reported explicitly.

Optical-flow tracking also applies an optional robust grayscale illumination correction against a fixed-camera reference. It estimates a bounded affine brightness transform from a majority of background pixels, rejecting moving foreground outliers. It does not alter the displayed camera feed, semantic model images, or infer a covered object as visible. This is enabled for live sessions; the standalone Tracker default stays unchanged. It assumes a fixed camera and cannot reconstruct blown highlights, deep noise, or fully occluded features.

Tests cover preserving hardware settings, readback verification/rollback, browser verification, an exposure jump with a foreground hand-like outlier, and existing motion tracking. Brightness desktop controls also retain the separately added two-second recovery window for brief camera interruptions; held-key output keeps its original watchdog behavior.
